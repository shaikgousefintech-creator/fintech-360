# FINTECH 360 - UPI Analytics & Business Insights

## 1. Overview

The UPI analytics module converts transaction-level data into analytical datasets, performance metrics and business insights.

It analyzes transaction performance across banks, payment applications, failure reasons, hours and weekdays.

The objective is to identify transaction patterns, compare performance and generate actionable recommendations for operational monitoring.

The analytics layer is implemented using Python and Pandas.

## 2. Analytical Components

The module generates five analytical datasets for failure and time-based analysis.

| Dataset | Analysis |
|---|---|
| `upi_bank_failure_analysis.csv` | Failure performance by payer bank |
| `upi_app_failure_analysis.csv` | Failure performance by payment application |
| `upi_failure_reason_analysis.csv` | Transaction failures by failure reason |
| `upi_hourly_analysis.csv` | Transaction performance by hour |
| `upi_weekday_analysis.csv` | Transaction performance by weekday |

Additional analytical outputs are generated by `src/analytics/upi_analytics.py`.

| Dataset | Purpose |
|---|---|
| `upi_overall_kpis.csv` | Overall UPI transaction metrics |
| `upi_daily_trends.csv` | Daily transaction performance |
| `upi_payment_app_performance.csv` | Payment application performance |
| `upi_payer_bank_performance.csv` | Payer bank performance |

## 4. Bank Failure Analysis

**Output:** `upi_bank_failure_analysis.csv`

Measures transaction volume, failed transaction count, failed transaction value and failure rate for each payer bank.

Observed findings:

- ICICI had the highest bank failure rate: 4.53%.
- PNB had the lowest bank failure rate: 3.59%.

**Business implication:**

Banks with comparatively higher failure rates should be investigated for possible transaction-processing, availability or response-time issues.

Bank-level performance monitoring can help identify institutions that require further operational investigation.

## 5. Payment Application Failure Analysis

**Output:** `upi_app_failure_analysis.csv`

Compares payment applications using total transactions, failed transactions, failed transaction value and failure rate.

Observed findings:

- BHIM had the highest failure rate: 4.41%.
- PhonePe had the lowest failure rate: 3.54%.

**Business implication:**

Payment application performance should be monitored to identify possible integration, routing and transaction-processing issues.

## 6. Failure Reason Analysis

**Output:** `upi_failure_reason_analysis.csv`

Identifies the most common reasons for failed transactions.

Observed findings:

| Failure Reason | Failed Transactions | Percentage of Failures |
|---|---:|---:|
| INSUFFICIENT_BALANCE | 106 | 26.30% |
| TRANSACTION_TIMEOUT | 106 | 26.30% |
| INVALID_VPA | 99 | 24.57% |

**Business implication:**

- Insufficient balance failures can be addressed through better customer guidance.
- Transaction timeout patterns should be investigated for possible processing delays or response issues.
- Invalid VPA failures highlight the importance of beneficiary information validation.

These findings identify common failure categories but do not independently establish their underlying root causes.

## 7. Hourly Transaction Analysis

**Output:** `upi_hourly_analysis.csv`

Analyzes transaction volume, successful transactions, failed transactions, pending transactions, transaction value and success/failure rates by hour.

Observed finding:

- 14:00 had the highest hourly failure rate: 6.62%, across 408 transactions.

**Business implication:**

Monitoring transaction processing and bank response times during higher-failure periods may help identify operational bottlenecks.

## 8. Weekday Transaction Analysis

**Output:** `upi_weekday_analysis.csv`

Compares transaction performance across weekdays.

Observed finding:

- Sunday had the highest weekday failure rate: 5.15%.

**Business implication:**

Monitoring service reliability and transaction failures on Sunday may help identify day-specific operational patterns.

## 9. Business Recommendations

The analytics outputs are converted into recommendations for operational investigation.

| Area | Observation | Recommendation |
|---|---|---|
| Bank performance | ICICI has the highest observed bank failure rate | Investigate bank-specific failures and response times |
| Payment application performance | BHIM has the highest observed app failure rate | Review application integration and error handling |
| Failure reasons | Insufficient balance and transaction timeout are common failure reasons | Improve customer guidance and investigate processing issues |
| Transaction timing | 14:00 has the highest observed hourly failure rate | Monitor transaction processing during this period |
| Weekday performance | Sunday has the highest observed weekday failure rate | Investigate day-specific service reliability patterns |

These recommendations are based on observed transaction patterns and should be treated as investigation priorities, not proof of root causes.

## 10. Key Analytical Metrics

The analysis uses the following measures:

- **Total Transactions:** Number of transaction records.
- **Successful Transactions:** Number of transactions with SUCCESS status.
- **Failed Transactions:** Number of transactions with FAILED status.
- **Pending Transactions:** Number of transactions with PENDING status.
- **Failed Transaction Value:** Sum of amounts for failed transactions.
- **Failure Rate:** Failed transactions divided by total transactions, multiplied by 100.
- **Success Rate:** Successful transactions divided by total transactions, multiplied by 100.
- **Transaction Value:** Sum of transaction amounts.
- **Average Transaction Amount:** Total transaction value divided by total transactions.

**Dashboard:** `src/dashboard/upi_dashboard.py`

The Streamlit dashboard presents analytical results through interactive visualizations.

Dashboard capabilities:

- Overall transaction KPI cards.
- Successful, failed and pending transaction metrics.
- Daily transaction volume and value trends.
- Transaction status distribution.
- Bank-wise transaction volume and success rate.
- Payment application performance comparison.
- Interactive date, bank and payment application filters.
- Transaction data exploration.
- Filtered CSV export.

The dashboard uses SQLite, Pandas and Plotly to present transaction and analytical mart data.
