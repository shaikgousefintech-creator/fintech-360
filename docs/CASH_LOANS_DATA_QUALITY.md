# FINTECH 360° - Cash Loans Data Quality

## 1. Overview

The Cash Loans module implements data quality validation at multiple stages to ensure that customer, loan product, application, disbursement and repayment data is accurate, complete and consistent.

Validation is performed across:

- Raw source datasets.
- Financial reconciliation.
- Python analytics outputs.
- Business insights outputs.

The validation framework uses Python, Pandas and SQL queries to identify data inconsistencies and verify loan and repayment calculations.

## 6. Loan and Repayment Validation Considerations

Cash Loans data involves multiple stages:

1. Loan application.
2. Application review and approval.
3. Loan disbursement.
4. Repayment installment generation.
5. Repayment collection.

These stages must be validated independently.

Important distinctions:

- An approved application does not necessarily result in a successful disbursement.
- Disbursement status and application status represent different business events.
- Repayment status describes individual installment outcomes.
- Partial payments must be distinguished from fully paid installments.
- Overdue installments must be identified using repayment status and applicable dates.

**Collection Ratio:**

The project's collection ratio is calculated as:

`Collected Amount / Total Due Amount`

For the current dataset, the denominator includes future pending installments. Therefore, this ratio should not be interpreted as a mature-loan recovery rate.

**Overdue Outstanding:**

Overdue outstanding represents installments classified as OVERDUE. It is not equivalent to total portfolio credit risk exposure.
